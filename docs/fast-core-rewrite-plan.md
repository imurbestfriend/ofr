# План нового конвейера анализа отчетности

Статус: план. Реализация еще не начата.
Ветка: `codex/fast-core-rewrite`.

## Результат

Одна консольная команда обрабатывает PDF одной компании из `reports/<Компания>/`
и создает TXT и Excel. В Excel обязательны четыре раздела:

- Описание компании — из материалов RA Expert.
- Метрики, риски и формы МСФО — из сохраненного TXT, извлеченного из PDF.

```text
PDF → TXT ──→ метрики, риски, МСФО ──┐
                                     ├→ Excel
RA Expert → описание компании ───────┘
```

Пример запуска:

```bash
venv/bin/python pipeline.py "reports/СИБУР" \
  --company "СИБУР" -w 2 -o outputs/sibur.xlsx
```

## Порядок обработки

1. Проверить PDF, настройки, зависимости, выходную папку и наличие однозначного
   досье RA Expert. При проблеме сообщить причину до отправки запросов.
2. Один раз извлечь текст всех PDF с помощью `pdftotext -layout` и разделить его
   по физическим страницам. Не запускать отдельное извлечение PDF для каждой
   категории анализа.
3. Записать полный извлеченный текст в UTF-8 TXT рядом с выходным Excel.
   Для каждой части сохранять имя PDF и номер страницы. Анализ читать именно
   из записанного TXT.
4. Передать текст модели крупными фрагментами. Для каждого фрагмента запрашивать
   компактный JSON с `metrics`, `risks` и `ifrs`. Обрабатывать весь извлеченный
   текст; не отправлять модельный запрос на каждую страницу и не пропускать
   содержательные страницы скрыто.
5. Получить описание компании отдельным запросом по исходным материалам
   выбранного досье RA Expert. Не извлекать это описание из PDF или TXT.
6. Объединить ответы по фрагментам и сформировать Excel с четырьмя разделами.
   Показать источник каждого PDF-показателя: документ, физическую страницу,
   цитату. Для описания сохранить ссылки на RA Expert.

Задачи RA Expert и PDF можно выполнять параллельно в пределах существующего
ограничения `-w`. Число запросов для PDF зависит от объема текста и ограничений
модели; заранее обещать один запрос на весь корпус нельзя.

## Требования к содержимому

- Извлекать все четыре раздела в каждом обычном запуске. Дополнительные режимы,
  выборочное ядро, переключатели и автоматический переход к другому конвейеру
  не добавлять.
- Описание компании строить только по исходным публикациям и текстам RA Expert.
  Использовать существующее досье, не запускать его сбор с сайта автоматически.
- Метрики извлекать с названием, периодом, значением, единицей и PDF-источником.
  Сохранять знак и явно указанные множители/ограничения.
- Риски брать из PDF-текста, сохранять существующий смысл результата. Не
  дополнять их данными RA Expert.
- МСФО представлять раскрытыми строками, формами и периодами, а не только
  несколькими сводными метриками. Не округлять и не исправлять суммы автоматически.
- Не выдавать явно описанные цели или прогнозы за факты. Неоднозначность отметить,
  а не разрешать догадкой.
- Пустое раскрытие отличать от ошибки обработки. Не придумывать отсутствующие
  показатели, риски или финансовые формы.

Текста сканированной страницы может быть недостаточно. В первой версии не делать
массовый OCR и рендер всех страниц: обозначать страницы без читаемого текста
в TXT и сообщать об ограничении в итоговом Excel.

## Входы и выходы

Сохранить консоль, папку `reports`, явный выбор компании `--company`, параллельность
`-w` и путь результата `-o`. Использовать сохраненные материалы `raexpert_output`;
обновление внешних источников остается отдельной операцией.

Если выходной файл — `outputs/sibur.xlsx`, текст сохранять как
`outputs/sibur.txt`. Структура Excel:

1. `Описание компании` — описание и источники RA Expert.
2. `Метрики` — значения, периоды и ссылки на PDF.
3. `Риски` — извлеченные риски и меры.
4. `МСФО` — финансовые формы и периоды.

Сохранять Excel через временный файл и публиковать только после успешной записи.
При ошибке оставить TXT и сообщение диагностики; предыдущую книгу не повредить.

## Как ускорять

1. Не извлекать и не перечитывать PDF повторно в рамках одного запуска.
2. Обрабатывать метрики, риски и МСФО одним анализом текстового фрагмента.
3. Использовать крупные фрагменты с нужным контекстом таблиц, вместо отдельных
   запросов на каждую страницу.
4. Получать описание RA Expert одним запросом; параллелить его с PDF-анализом.
5. Не запускать массовый OCR, полный рендер страниц или сложный геометрический
   анализ в основном пути.
6. Ограничить повторы API и ожидание, чтобы временная ошибка не зацикливала запуск.

Кэширования и повторного использования результатов предыдущих запусков пока нет.
Обещание времени 60–180 секунд снято: сначала измерить новый путь на полном
требуемом результате, включая риски, МСФО и описание компании.

## План реализации

1. Зафиксировать JSON-формат ответов трех разделов PDF и структуру Excel.
2. Реализовать пакетный PDF → TXT с источниками и проверкой покрытия страниц.
3. Реализовать TXT → JSON → Excel для метрик, рисков и МСФО.
4. Подключить описание и ссылки из материалов RA Expert.
5. Добавить объединение фрагментов, ограниченные повторы и параллельность.
6. Испытать полный запуск на СИБУРе и НОВАТЭКе; записать длительность этапов,
   число запросов и токены. Сверить все четыре раздела с источниками.
7. Исправить обнаруженные потери, затем повторить испытание на других компаниях.
8. Обновить справку и инструкцию для обычной команды запуска.
9. Рассматривать кэширование только после проверки нового конвейера.

Старую сложную реализацию не переносить целиком. Переиспользовать отдельные
небольшие функции, только если они нужны новому пути. Новые серверы, интерфейсы,
БД, RAG, систему возобновления и переключатели режимов не строить.

## Критерии готовности

- Все входные PDF проходят один путь извлечения; полный извлеченный текст доступен
  в TXT, разбитый по документам и физическим страницам.
- Метрики, риски и МСФО построены из TXT; описание компании построено из RA Expert.
- Все четыре раздела присутствуют в сохраненном Excel.
- Источники и цитаты позволяют проверить извлеченные значения.
- Ошибки PDF, API, JSON и записи Excel не выдают пустой результат за успешный.
- Тесты проходят по PDF → TXT → Excel; реальные запросы к API подтверждают качество
  и время полного запуска.
- Производительность оценивается на одинаковых входных файлах и модели. Результат
  с пропущенными страницами или разделами не считается успешным ускорением.

Незакоммиченные изменения и пользовательские файлы в рабочей папке сохранять.
Текущий коммит содержит только план; реализация переписывания еще не началась.
